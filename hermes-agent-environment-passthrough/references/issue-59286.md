# GitHub Issue #59286: terminal env_passthrough not honored by Daytona backend

## Summary
The Daytona backend was not passing environment variables to the sandbox, causing
`terminal.env_passthrough` and skill `required_environment_variables` to be ignored.

## Root Cause
`DaytonaEnvironment._run_bash()` called `sandbox.process.exec(shell_cmd, timeout=timeout)`
without an `env=` argument, so commands saw only the sandbox's default environment.

## Fix (implemented)
Added inline `passthrough_env` filtering inside `_run_bash()` in
`tools/environments/daytona.py`:

- Imports `is_env_passthrough` from `tools.env_passthrough`
- Filters `os.environ` through `is_env_passthrough()` (which already blocks
  Hermes-managed provider credentials per GHSA-rhgp-j443-p4rf)
- Passes the filtered dict as `env=` to `sandbox.process.exec()`

The SDK's `Process.exec()` supports `env=` — verified by reading the source:
`daytona/_sync/process.py` line 100 accepts `env: dict[str, str] | None = None`.

## PR
